# DroidDeck 0.1.0

The third public release of DroidDeck: a local Windows control deck for Android
devices. This release improves Gradle project detection and run configuration,
routes shell dialogs through one service, and continues the internal deepening
work from `0.0.2-alpha`. DroidDeck is still pre-1.0 and alpha quality.

DroidDeck has no accounts, telemetry, or cloud sync. Settings, logs, diagnostics,
and plugin data stay on the computer.

## Highlights

- **Gradle plugin resolution.** Project detection now resolves the plugins a
  build applies through version-catalog aliases, `apply false` declarations,
  convention plugins from `buildSrc` and included builds, and plugin markers.
  The effective plugin set is computed once and shared by the detector.
- **Variant-aware application IDs.** Variant detection composes application IDs
  from flavor and build-type suffixes, honours `defaultFlavor`, and qualifies
  names when several application modules exist. Run configurations seed the
  module, package name, build task, and APK glob from the selected variant.
- **One shell dialog service.** Content dialogs are serialized for the shell
  window, overlapping dialog attempts are logged and blocked, and every file
  picker is initialized with the window handle instead of repeating per-page
  XAML root handling.
- **Concurrent toolchain doctor.** Probes come from one spec table and run
  concurrently, while the .NET task stays available to the MAUI workload probe.
- **Faster settings merge.** Reads, writes, flattening, and merging share one
  document traversal and reuse the casing already stored in the file; merge now
  performs one lookup per key.
- **Hardened plugin boundaries.** Package download and archive extraction moved
  into a package acquirer that owns redirects, size caps, hash checks, path
  escapes, reserved device names, duplicate entries, extraction caps, and
  cleanup. Manifest metadata rules can now be validated without touching the
  filesystem.
- **Reliable plugin secret names.** Pairs whose length-prefixed name exceeds the
  store limit fall back to a stable hashed name, and legacy entries migrate on
  read as well as write.

## Fixes

- Long, valid plugin ids and secret field keys no longer fail the whole lookup;
  removal deletes both the current and legacy names.
- Opening a dialog while another is active is reported as a blocked dialog
  instead of an exception, and file pickers no longer depend on which page
  opened them.
- Gradle projects that apply plugins through a version catalog, a convention
  plugin, or a flavor now produce the expected plugin set, application ID, and
  run task instead of falling back to project defaults.

## Requirements

- Windows 10 1809 or newer, x64; Windows 11 is the supported target and
  Windows 10 22H2 is best effort.
- No .NET runtime or Windows App SDK runtime is required for this portable
  build.
- Android SDK platform-tools (`adb`) for real devices, and scrcpy for mirroring.
  Both are optional for starting the app.

## Install

1. Download `DroidDeck-0.1.0-win-x64.zip` below.
2. Verify the checksum against `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\DroidDeck-0.1.0-win-x64.zip -Algorithm SHA256
   Get-Content .\SHA256SUMS.txt
   ```

3. Extract the zip and run `DroidDeck.exe` from the
   `DroidDeck-0.1.0-win-x64` folder.
4. Optionally create an empty `portable.marker` file beside `DroidDeck.exe` to
   keep settings and logs in a `data` folder beside the app instead of
   `%LocalAppData%\DroidDeck`.

This release is not code-signed. Windows SmartScreen may say "Windows protected
your PC" or identify an unknown publisher. Only bypass the warning after the
checksum matches the published value.

Upgrading from `0.0.2-alpha`: replace the portable folder and keep your data
directory. Settings and plugin data remain compatible.

## Plugin SDK packages

The four SDK packages are attached to this release because they are not
published to nuget.org. Download them into one folder and install the templates:

```text
dotnet tool install --global DroidDeck.PluginPack --add-source <sdk-folder> --version 0.1.0
dotnet new install DroidDeck.Plugin.Templates.0.1.0.nupkg
```

Add `<sdk-folder>` as a package source in `NuGet.config` so generated projects
can restore `DroidDeck.Plugin.Abstractions` and `DroidDeck.Plugin.UI`. Generated
plugins default to `sdkVersion` and `minHostVersion` `0.1.0`, so they require
this host or a later compatible one. See the
[authoring guide](https://github.com/raulshma/droiddeck/blob/main/docs/plugin-sdk/authoring.md)
for the full setup.

## Known limitations

- **Alpha quality.** Plugin APIs, settings schemas, and UI may change before
  1.0.0. Back up plugin data before upgrading.
- **Unsigned binaries.** Expect a SmartScreen warning; verify the checksum.
- **No installer or auto-update.** Upgrade by replacing the portable folder and
  keeping your data directory.
- **Update checks see stable releases only.** `0.1.0` is the latest stable
  release, so the in-app check can report it; prereleases remain invisible
  until a later stable release exists.
- **Deferred release gates.** The clean-machine portable pass and the hands-on
  accessibility pass are deferred under the
  [pre-1.0 alpha policy](https://github.com/raulshma/droiddeck/blob/main/docs/release.md#pre-10-alpha-policy);
  the automated suites, size budget, startup measurement, and security suites
  did run.
- **Eight-hour soak deferred with an accepted risk.** The run-finalization and
  multi-device start changes touch session paths behaviourally, so the
  eight-hour soak was not run. Testers who keep long runs open should watch for
  orphaned `adb` or `scrcpy` processes and report them.
- **Plugins are in-process and unsandboxed.** Only install plugins you trust;
  prefer plugins that ship source.
- **Only the portable `win-x64` build is published.** There is no ARM64 build,
  installer, or Store package for this release.

## Security and privacy

The candidate was rechecked against the
[release security review](https://github.com/raulshma/droiddeck/blob/main/docs/security-review.md).
Process execution stays on `UseShellExecute = false` with argument lists, plugin
trust and hash verification still precede extraction, catalog downloads remain
HTTPS-only with size and schema limits, and the new package acquirer rejects
path escapes and reserved device names before writing files. Secrets stay on
DPAPI, update checks stay manual, and safe mode still disables third-party code.
The six recorded residual risks are unchanged, with no open remediable high or
medium finding. Review the trust prompt before approving a plugin, and report
vulnerabilities privately as described in
[Security](https://github.com/raulshma/droiddeck/blob/main/docs/security.md).

## Evidence

- Size: 235.6 MiB extracted and 94.0 MiB zipped, inside the 250 MiB and 120 MiB
  budgets.
- Startup: median 1094 ms and p95 1224 ms over eight measured runs after two
  warmups, inside the 2,000 ms and 3,000 ms budgets.
- The portable zip was extracted and launched; after one warmup the extracted
  copy measured a 888 ms median over three runs.
