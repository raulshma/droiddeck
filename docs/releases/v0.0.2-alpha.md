# DroidDeck 0.0.2-alpha

The second alpha of DroidDeck: a local Windows control deck for Android devices.
This is an architecture-hardening release. No new user-facing features were
added; device, plugin, run, project, and screen behaviour were consolidated so
each concern has one implementation and one policy.

DroidDeck has no accounts, telemetry, or cloud sync. Settings, logs, diagnostics,
and plugin data stay on the computer.

## Highlights

- **One adb command path.** Device identity is the single `DeviceInfo` record,
  and every adb caller shares one executor for device arguments, timeouts, and
  failure classification. The toolbox now reports text-detected failures as
  failures even when adb exits zero.
- **One plugin policy.** The validator, catalog, installer, and loader share one
  compatibility and dependency truth table. Catalog installs reject an
  incompatible API or host version before downloading.
- **One settings store.** A single factory owns schema parsing, secret-store
  checks, and per-file store reuse. A missing secret store now falls back to the
  raw store with a surfaced warning instead of failing the plugin.
- **One install state.** Update, rollback, trust, and version reconciliation are
  computed once outside the Extensions page, so the offered actions cannot drift
  from the installed contents.
- **One supervised session.** Flutter and Metro runs compose one supervised
  child-process session for line events, stderr tails, graceful stop, and
  process-tree kill; run sessions finalize through one method with one lock
  discipline.
- **One settings value policy.** Health checks and editors read the same bounds,
  and the run concurrency clamp honours the documented maximum.
- **One project refresh table.** Capacitor and Cordova share a web-hybrid
  adapter, detector helpers are single-sited, and compare and apply are driven
  by one field table.
- **One remote capture.** Screenshots and thumbnails share the temporary remote
  path, pull, cleanup, and failure handling.

## Fixes

- Emulator console snapshot failures reported as `KO` at exit zero stay failures.
- Loaded and failed plugins keep the loader's validation warnings in their
  status, and plugin settings schema warnings are logged.
- The Extensions page reconciles statuses with the installed versions, so an
  update is not offered again after a catalog install or rollback.
- Catalog entries with invalid host-range boundaries are reported as
  incompatible instead of compatible.

## Requirements

- Windows 10 1809 or newer, x64; Windows 11 is the supported target and
  Windows 10 22H2 is best effort.
- No .NET runtime or Windows App SDK runtime is required for this portable
  build.
- Android SDK platform-tools (`adb`) for real devices, and scrcpy for mirroring.
  Both are optional for starting the app.

## Install

1. Download `DroidDeck-0.0.2-alpha-win-x64.zip` below.
2. Verify the checksum against `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\DroidDeck-0.0.2-alpha-win-x64.zip -Algorithm SHA256
   Get-Content .\SHA256SUMS.txt
   ```

3. Extract the zip and run `DroidDeck.exe` from the
   `DroidDeck-0.0.2-alpha-win-x64` folder.
4. Optionally create an empty `portable.marker` file beside `DroidDeck.exe` to
   keep settings and logs in a `data` folder beside the app instead of
   `%LocalAppData%\DroidDeck`.

This release is not code-signed. Windows SmartScreen may say "Windows protected
your PC" or identify an unknown publisher. Only bypass the warning after the
checksum matches the published value.

Upgrading from `0.0.1-alpha`: replace the portable folder and keep your data
directory. Settings and plugin data remain compatible.

## Plugin SDK packages

The four SDK packages are attached to this release because they are not
published to nuget.org. Download them into one folder and install the templates:

```text
dotnet tool install --global DroidDeck.PluginPack --add-source <sdk-folder> --version 0.0.2-alpha
dotnet new install DroidDeck.Plugin.Templates.0.0.2-alpha.nupkg
```

Add `<sdk-folder>` as a package source in `NuGet.config` so generated projects
can restore `DroidDeck.Plugin.Abstractions` and `DroidDeck.Plugin.UI`. See the
[authoring guide](https://github.com/raulshma/droiddeck/blob/main/docs/plugin-sdk/authoring.md)
for the full setup.

## Known limitations

- **Alpha quality.** Plugin APIs, settings schemas, and UI may change before
  1.0.0. Back up plugin data before upgrading.
- **Unsigned binaries.** Expect a SmartScreen warning; verify the checksum.
- **No installer or auto-update.** Upgrade by replacing the portable folder and
  keeping your data directory.
- **Prereleases are invisible to update checks.** The in-app check reads the
  latest stable GitHub release, so it reports no update while only prereleases
  exist.
- **Deferred release gates.** The clean-machine portable pass and the hands-on
  accessibility pass are deferred under the
  [pre-1.0 alpha policy](https://github.com/raulshma/droiddeck/blob/main/docs/release.md#pre-10-alpha-policy);
  the automated suites, size budget, startup measurement, and security suites
  did run.
- **Eight-hour soak deferred with an accepted risk.** This release refactors the
  supervised child-process path used by session and mirror runs. The refactor is
  covered by the session, process, and screen suites, but the eight-hour soak
  was not run. Testers who keep mirrors or long runs open should watch for
  orphaned `adb` or `scrcpy` processes and report them.
- **Plugins are in-process and unsandboxed.** Only install plugins you trust;
  prefer plugins that ship source.
- **Only the portable `win-x64` build is published.** There is no ARM64 build,
  installer, or Store package for this alpha.

## Security and privacy

The candidate was rechecked against the
[release security review](https://github.com/raulshma/droiddeck/blob/main/docs/security-review.md).
The refactors keep process execution on `UseShellExecute = false` with argument
lists, keep plugin trust and hash verification before extraction, and keep
catalog downloads HTTPS-only with size and schema limits. The six recorded
residual risks are unchanged, with no open remediable high or medium finding.
Review the trust prompt before approving a plugin, and report vulnerabilities
privately as described in
[Security](https://github.com/raulshma/droiddeck/blob/main/docs/security.md).
