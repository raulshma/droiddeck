# DroidDeck 0.2.0

The fourth public release of DroidDeck: a local Windows control deck for Android
devices. This release adds a per-user installer and code-signed release
artifacts, and consolidates the shell: one sidebar for every screen, command
menus in the title bar, and docked mirror windows that embed into the app.
DroidDeck is still pre-1.0 and alpha quality.

DroidDeck has no accounts, telemetry, or cloud sync. Settings, logs, diagnostics,
and plugin data stay on the computer.

## Highlights

- **Windows installer.** Releases now ship a per-user
  `DroidDeck-setup-win-x64.exe` built with Inno Setup. It installs to
  `%LocalAppData%\Programs\DroidDeck` without administrator rights, adds
  Start-menu and optional desktop shortcuts, and registers an uninstall entry
  under Settings > Apps. Upgrades install in place and keep the data directory.
- **Code-signed release assets.** Every released executable and library, the
  installer, and the four SDK packages are signed with DroidDeck's
  self-signed code-signing certificate and an RFC 3161 timestamp, and the
  release workflow fails if any asset is unsigned, mistimestamped, or signed
  by another certificate.
- **One sidebar for every screen.** Device tools, mirror, performance,
  inspector, and session join the existing entries; the pane scrolls when the
  window is short, and settings, diagnostics, and about stay pinned at the
  bottom.
- **Title-bar command menus.** The command menus moved into the title bar row
  next to the app title and connected-device count, freeing a row of vertical
  space; the menu bar stays clickable over the drag region.
- **Embedded mirrors.** Docked scrcpy windows embed into the app window, so
  the taskbar no longer shows a separate entry per mirror.
- **Mirror from Home.** Home device rows open the screen mirror for that
  device directly, and the settings page switched to selector bar tabs.

## Fixes

- Embedded window state is guarded by a lock, fixing crashes when stopping a
  mirror.

## Requirements

- Windows 10 1809 or newer, x64; Windows 11 is the supported target and
  Windows 10 22H2 is best effort.
- No .NET runtime or Windows App SDK runtime is required for either the
  installer or the portable build.
- Android SDK platform-tools (`adb`) for real devices, and scrcpy for
  mirroring. Both are optional for starting the app.

## Install

1. Download `DroidDeck-0.2.0-setup-win-x64.exe` (or the portable zip) below.
2. Verify the checksum against `SHA256SUMS.txt`:

   ```powershell
   Get-FileHash .\DroidDeck-0.2.0-setup-win-x64.exe -Algorithm SHA256
   Get-Content .\SHA256SUMS.txt
   ```

3. Run the installer. It needs no administrator rights. To install without
   shortcuts or to script it, run `DroidDeck-0.2.0-setup-win-x64.exe /SILENT`.

   The portable alternative is `DroidDeck-0.2.0-win-x64.zip`: extract the
   folder and run `DroidDeck.exe` from it. Optionally create an empty
   `portable.marker` file beside `DroidDeck.exe` to keep settings and logs in
   a `data` folder beside the app instead of `%LocalAppData%\DroidDeck`.

Release binaries are signed, but the certificate is self-signed, so Windows
SmartScreen may still show "Windows protected your PC". Only bypass the
warning after the checksum matches. The signing certificate is:

```text
SHA-256 fingerprint:
414C20FE3574D2219DCF771601EA8ADF5519176FE178285121B9F7691A7AAF36
```

Upgrading from `0.1.0`: run the new installer over the old one, or replace
the portable folder. Settings and plugin data remain compatible.

## Plugin SDK packages

The four SDK packages are attached to this release because they are not
published to nuget.org. Download them into one folder and install the
templates:

```text
dotnet tool install --global DroidDeck.PluginPack --add-source <sdk-folder> --version 0.2.0
dotnet new install DroidDeck.Plugin.Templates.0.2.0.nupkg
```

Add `<sdk-folder>` as a package source in `NuGet.config` so generated projects
can restore `DroidDeck.Plugin.Abstractions` and `DroidDeck.Plugin.UI`. Generated
plugins default to `sdkVersion` and `minHostVersion` `0.2.0`, so they require
this host or a later compatible one. See the
[authoring guide](https://github.com/raulshma/droiddeck/blob/main/docs/plugin-sdk/authoring.md)
for the full setup.

## Known limitations

- **Alpha quality.** Plugin APIs, settings schemas, and UI may change before
  1.0.0. Back up plugin data before upgrading.
- **Self-signed code-signing certificate.** Signatures prove the artifacts
  came from this release pipeline, but they carry no certificate-authority
  endorsement, so SmartScreen still warns. Verify the checksum and the
  fingerprint above.
- **Deferred release gates.** The clean-machine portable pass and the
  hands-on accessibility pass are deferred under the
  [pre-1.0 alpha policy](https://github.com/raulshma/droiddeck/blob/main/docs/release.md#pre-10-alpha-policy);
  the automated suites, size budget, installer budget, and startup
  measurement did run.
- **Eight-hour soak not run.** The `0.2.0` changes are shell and window
  integration and do not touch the session paths that made the soak a
  deferred risk at `0.1.0`, but the embedded-window work is new shell
  integration. Testers who keep long mirrors open should watch for orphaned
  `adb` or `scrcpy` processes and report them.
- **Plugins are in-process and unsandboxed.** Only install plugins you trust;
  prefer plugins that ship source.
- **Only `win-x64` is published.** There is no ARM64 or Store package.

## Security and privacy

Signing adds no runtime surface: the app and its data handling are unchanged
from `0.1.0`, whose
[release security review](https://github.com/raulshma/droiddeck/blob/main/docs/security-review.md)
recorded no open remediable high or medium finding and six unchanged residual
risks. The signing identity is managed as follows: the JKS keystore lives
outside the repository, the release workflow receives the keystore and
passwords through GitHub Actions secrets, converts the keystore to PFX into
the runner temp directory per run, and deletes the material when the run
ends; signature verification imports the public certificate only into the
ephemeral runner trust store. Review the trust prompt before approving a
plugin, and report vulnerabilities privately as described in
[Security](https://github.com/raulshma/droiddeck/blob/main/docs/security.md).
